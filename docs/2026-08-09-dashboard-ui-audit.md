## Verdict

The dashboard is structurally sound and unusually disciplined about evidence honesty — `ResourcePanel`'s precedence chain (`apps/dashboard/src/components/panel.tsx:88-96`), the `Bounded`/`truncated` plumbing, the `Unavailable` component with explicit labels, and the comment at `apps/dashboard/src/routes/usage-view.tsx:11-15` show a codebase that took the "empty ≠ not-observed ≠ unavailable" rule seriously and mostly kept it. What it has not done is hold that line everywhere, and it has not held its own visual contract at all in one theme. Three concrete classes of problem survive verification: (1) the light theme, which the app auto-enters purely from OS preference with no toggle and no override anywhere in `.tsx` (`apps/dashboard/index.html:6`; the entire `:root[data-theme='light']` block at `tokens.css:95-124` is unreachable dead code), renders the inspector drawer illegible; (2) four places where an _unavailable_ read is rendered as an observed fact — a hard `0`, an empty-filter message, or a complete-looking list; and (3) the keyboard path is degraded by a skip link that destroys the user's route. Everything else is depth: many daemon read endpoints have no consumer, and several routes are thinner than their siblings. None of the depth items is a malfunction, and none of them is a scope violation to be fixed silently — several are new scope.

## 1. The light theme is broken on the primary drill-down surface (most consequential)

This cluster was found independently by two audit dimensions and corroborates itself. The root cause is a split token layer: `@media (prefers-color-scheme: light)` (`apps/dashboard/src/styles/tokens.css:69-93`) redefines 21 tokens, while the fuller, better-tuned light set lives in `:root[data-theme='light']` (`tokens.css:95-124`) — and nothing in the app ever sets `data-theme` (grep matches only `tokens.css` and built dist CSS). So the reachable light path is the smaller, incomplete block.

**Illegible in light theme (major):**

- `apps/dashboard/src/styles/activity.css:141` — `.inspector > header { background: rgba(12, 13, 20, 0.96) }`, the dark `--bg-raised` inlined, while the panel body one rule above (`activity.css:129`) correctly uses `var(--bg-raised)`. `.inspector h2, .inspector h3` (`activity.css:143-146`) declares only `margin: 0`, so the title inherits `--text` = `#0d111c`. Composited ground ≈ `#16171d` → **~1.05:1**. The dialog's own title (`inspectors/inspector-panel.tsx:213`) is effectively invisible.
- `apps/dashboard/src/styles/activity.css:187-188` — `.inspector-json` pairs `color: var(--text-secondary)` (`#2c3444` in light) with `background: #08090e` → **~1.6:1**. That element (`inspectors/inspector-panel.tsx:281`) renders every inspected event's payload; it is the inspector's densest evidence surface.

**Missing tokens on the reachable light path (major):**

- `--focus` is declared once, at `tokens.css:59`, and appears in neither light block. All three application sites pair it with `outline: none` — `shell.css:25-29` (every `a` and `button`), `activity.css:57-62`, `projects.css:51-55` — so the UA ring is discarded first. Composite on white is `#c6cbfc`, **~1.57:1**, under the 3:1 non-text floor. This is the app-wide keyboard indicator. That `--magnitude-fill` _is_ darkened for light (`tokens.css:29` → `:86`/`:111`) shows the omission is an oversight, not a decision.
- The seven `--graph-*` tokens are absent from `tokens.css:69-93` and exist light-tuned only at `tokens.css:112-118`. Dark hues therefore render on `--bg-raised: #ffffff` (`projects.css:279`). Recomputed: `--graph-history` `#179fd4` ≈ 2.75:1, `--graph-structure` `#b38c15` ≈ 3.14:1, `--graph-operational` `#8792a8` ≈ 3.13:1 at full opacity — and `edgeStroke` (`routes/graph-diagram.tsx:111-115`) draws edges at 0.9/0.8/0.7/**0.45** opacity, so unknown-confidence edges land far under 3:1. Four of seven hues pass; 2–3 do not.

**Minor in the same family:**

- `--selection` is likewise defined once (`tokens.css:24`) and never re-tokenised, while its companion `--selection-soft` _is_ overridden at `:82` and `:107`. `.skip-link` (`shell.css:40-49`) puts `var(--text)` on it: **4.03:1 dark, 4.24:1 light**, both short of 4.5:1 AA for 14px text.
- `pulse.css:192` hardcodes `#a78bfa` for `adapter-extracted` while its four siblings (`pulse.css:185-199`) use `--success`/`--info`/`--warning`/`--unknown`, all of which flip for light. ≈2.7:1 on white. The provenance is also rendered as text (`pulse/pulse-view.tsx:219`), so no evidence distinction is lost — one of five peer categories just renders materially fainter.
- `.identity__mark` (`shell.css:78-88`) declares no `color` over a hardcoded `linear-gradient(145deg, #0b66dc, #4f46e5)`, so the glyph inherits `--text` and inverts in light (3.0–3.6:1). WCAG 1.4.3 exempts brand marks, so treat this as token hygiene — but `#0b66dc`/`#4f46e5` are `--luwi-blue`/`--luwi-accent-lo` written as literals with no production token (also at `shell.css:284`).

There is no automated guard on any of this, though the repo already tests CSS strings (`styles/shell.test.ts:5-15`) and dashboard invariants (`product-independence.test.ts:28-73`). A guard must be written carefully: the worst offender is a translucent `rgba()`, and a blanket hex/rgba ban would false-positive on legitimate overlays at `activity.css:14, 122, 130` and `shell.css:84`.

## 2. Unknown evidence rendered as a stronger claim

Four confirmed violations of the rule the rest of the codebase defends well. All were reproduced by rendering, not inferred.

- **An unavailable sessions read renders as a hard `0`, in three places (major).** `pulse/model.ts:132-165` returns `sessions: []` when the read is unavailable, so `projects[].activeSessions` computes to `0` while the truth survives only in `sessionsState` (`model.ts:217`). Rendered at `routes/agents-view.tsx:62`, `projects/projects-view.tsx:145`, and `pulse/pulse-view.tsx:187`. On Pulse this makes one screen contradict itself: "0 active" sits directly beneath a panel reading "Session data unavailable". No test covers it — `routes.test.tsx:252-266` and `projects-view.test.tsx:167-174` exercise sessions only in the _ready_ state. The fix belongs in the model: `activeSessions` should carry a `CountValue` like `activeSessionCount` already does (`model.ts:150-156`).
- **An unavailable activity read renders as "No activity matches these filters" (major).** `ActivityView`'s props carry no availability channel (`activity/activity-view.tsx:12-20`); `model.ts:213` flattens a failed read to `[]`; `activity-view.tsx:162-163` shows the filter message for all three situations. Pulse gets the same distinction right (`pulse-view.tsx:312-315`). The same render also shows "**0 retained events**" in the command bar, because `app.tsx:115` pluralizes `snapshot.activity.length` with no availability check. Grepping all tests returns zero matches for either "No activity matches" or "No retained activity".
- **OptimizationView silently drops the `truncated` flag (major).** `proposals` is `Bounded<OptimizationProposal>` fetched at limit 100 with `truncated` carried through (`api/intelligence-scope.ts:73, 152, 160`), and `routes/optimization-view.tsx:79-128` never reads it. A user looking at 100 proposals is shown a complete-looking list. Both siblings do this correctly and are tested — `context-view.tsx:96-100` / `intelligence-routes.test.tsx:103-112`, and `projects-view.tsx:82-89` / `projects-view.test.tsx:261-266`. One-line fix plus a mirror test.
- **Pulse and Usage disagree about a missing token total (minor).** `usage-view.tsx:46-52` renders an absent `totalTokens` as `Not reported`, with the reason documented at `usage-view.tsx:12-15` and pinned by `routes.test.tsx:294-298`. `pulse-view.tsx:220` renders the identical field as `?? 'Unavailable'`, so the Pulse row shows the word "Unavailable" twice with two different meanings. `app.test.tsx:91-96` only asserts `getAllByText(label).length > 0`, which the source-label cell alone satisfies — the test cannot detect this.

**Adjacent, and weaker than the above:** three routes label an in-flight read as a fault. `intelligenceResources` starts `{}` (`main.tsx:127-129`), is filled only after first paint (`main.tsx:142-152`), and `panel.tsx:84` coerces `undefined` to `{state:'unavailable'}`. On the first paint of `#/context`, `#/optimization` and `#/graph` the sources, proposals, projection and by-kind panels read "Unavailable". A test locks this in: `intelligence-routes.test.tsx:91-96` asserts `sources={undefined}` must show "Unavailable". It is transient and self-corrects on a loopback round trip, so it is minor — but it is the one place where the suite defends a claim stronger than the evidence, and the correct pattern exists twice in-tree (`projectScopeLoading` at `main.tsx:118, 161, 170` rendered at `projects-view.tsx:158-159`; the `aria-busy` branch at `graph-explorer-view.tsx:220-223`).

**Two Pulse rows assert a fault with no data source at all.** `pulse-view.tsx:293-296` and `:297-300` render literal `<dd>Unavailable</dd>` for "Function library" and "Projection health" — no props, no snapshot field, no conditional. Projection health _does_ exist in the model (`api/intelligence-scope.ts:65`) and is rendered on the Graph route (`routes/graph-view.tsx:71-77`), so Pulse asserts a fault the runtime can disprove. Wiring Pulse to the graph summary would be wrong — `main.tsx:65-74` keeps it off the bootstrap deliberately, since ADR 0013 puts it at 56 Redis commands. Delete the rows or reword them as "Not read on this route". No daemon route exposes Redis function-library state at all, so that row has no possible source.

## 3. The keyboard path

- **The skip link destroys the route (major).** `app.tsx:197-199` renders `<a className="skip-link" href="#main-content">` as the first focusable element (`shell.css:40-51`). Activating it writes `#main-content` into `location.hash`; `routing.ts:50-66` finds `main-content` in neither `SIMPLE_ROUTES` (`:19-27`) nor the `projects` branch and falls through to `return { name: 'pulse' }` at `routing.ts:66`. `app.tsx:175-179` swaps the route, and `main.tsx:133-140` independently recomputes from the same hash, clearing the project selection (`main.tsx:154-173`) and switching intelligence loading off (`main.tsx:142-152`). The one control whose entire purpose is to help keyboard and screen-reader users is the one that resets their context. Grep for `skip`/`main-content` across every test file returns nothing. Fix inside the existing design: `tabIndex={-1}` on `<main>` plus `preventDefault()` + `main.focus()`, or have `parseRoute` return the current route for a non-route fragment. Needs a test either way.
- **The inspector steals focus back on every parent re-render (major).** `inspector-panel.tsx:156-165` runs `closeButton.current?.focus()` in an effect keyed on `close`, which is `useCallback(..., [onClose])` (`:151-155`); `onClose` is `app.tsx:187`'s inline `closeInspector`, recreated every render, and `InspectorPanel` is rendered inline at `app.tsx:383-392` with no memoization. Every accepted realtime event (`main.tsx:260-277`) and every refresh (`main.tsx:216-233`) therefore re-fires the focus call. Harmless while focus is already on Close; disruptive for anyone who has moved focus inside the open dialog. The effect is also doing two jobs — split the initial focus (keyed on selection identity) from the Escape listener.
- **`aria-modal="true"` is a promise the markup does not keep (major).** `inspector-panel.tsx:204-209` declares it; there is no Tab handler, no `inert`, no `aria-hidden` anywhere in the file. The dialog is a sibling rendered after `</main>` (`app.tsx:383-392`), so tab order continues past it into the background — which `aria-modal` has already removed from the AT tree. A screen-reader user who tabs past Close lands on controls their reader cannot describe. Either implement containment or drop `aria-modal` and call it a drawer honestly. Dismissal itself is fine in both input modes (Escape at `:158-162`, backdrop mousedown at `:200-202`).

**Smaller, verified:**

- Graph node selection is mouse-only: `graph-diagram.tsx:210-216` is a bare `<g onClick>` with no role/tabIndex/key handler inside an `<svg role="img">`, and the state is colour-only (`projects.css:294-296, 357-359`). Narrow, because identity, kind, origin and the re-root action are all keyboard-reachable in the Nodes table (`graph-explorer-view.tsx:251-291`) — the only thing lost is the highlight, which above 26 nodes (`graph-diagram.tsx:33`) is what reveals a node's label. The header comment at `graph-diagram.tsx:16` still claims the diagram is `aria-hidden`; it is `role="img"` at `:179`.
- Six `aria-label`s sit on name-prohibited generic elements (`app.tsx:276`; `inspector-panel.tsx:254`; `activity-view.tsx:92, :117, :155-159`; `sessions-view.tsx:120`; `graph-explorer-view.tsx:169`). Only one has a real consequence: `activity-view.tsx:155-159` gives `tabIndex={0}` to a role-less div, making it a tab stop that may announce nothing. `role="log"` there and `role="group"` on the filter wrappers legitimises all of them.
- Four live regions are mounted together with their text, so the first announcement is unreliable: `app.tsx:280-284`, `sessions-view.tsx:146-150`, `graph-explorer-view.tsx:230-235`, `pulse-view.tsx:46-56`. The correct pattern is already in-tree at `activity-view.tsx:46-69, 92-94` (always mounted, 750 ms debounce).
- Polish: `aria-selected="false"` on every project row (`projects-view.tsx:134`) with colour-only selection (`projects.css:56-62`); duplicated route headings on Activity and Sessions only (`app.tsx:55, 58` vs `activity-view.tsx:98` and `panel.tsx:52-56`); project selection as a `<button>` (`projects-view.tsx:136-142`) that assigns a hash `routing.ts:69-77` can already produce as an `href`; `scope="col"` missing on `pulse-view.tsx:117-126` alone; five caption-less hand-built tables in `projects-view.tsx`; `IdBadge`'s "Copied" confirmation invisible to AT (`components/id-badge.tsx:35-42`, static `aria-label` at `:39` overrides the changing text) with two silent failure paths at `:21` and `:25`.

## 4. Data coverage — read endpoints with no consumer

These are gaps, not defects; nothing is misrendered. Ranked by what a user actually loses.

- **Inter-agent messaging has no read view at all.** `apps/daemon/src/app.ts:844` and `:850` serve the full record set read-only with filtering by project/source/target/state (`packages/protocol/src/message.ts:152-164`). Eight `message.*` event types exist (`runtime-event.ts:17-24`) and `realtime/schema.ts:52` explicitly accepts the `message.` prefix into Activity — so a user sees that a request was made and later timed out, but never who asked whom, the subject, the state, or the response. `packages/protocol/src/browser.ts` (19 lines) does not even re-export the schemas. `planned` at `app.tsx:36` is empty, so the rail gives no signal this domain exists.
- **Capability and profile catalogues are unreachable while their counts are displayed.** `app.ts:1019, 1041, 1081, 1094` are all GET and all unconsumed, while `api/project-scope.ts:273-274` reduces bindings to `profileCount`/`capabilityCount` and `projects-view.tsx:185-186, 200-201` renders exactly those two numbers. This is the one coverage gap with a concrete user-visible dead end: a number whose contents cannot be opened.
- **Effective agent configuration and its conflicts are never read.** `app.ts:1108-1116` returns `valid`, `conflicts`, `missingDependencies`, `unsupportedCapabilities`, `nativeCapabilitySupport`, `estimatedContextFootprint` (`control-plane.ts:381-395`). The two counts above are the only binding facts on screen, so there is no partial substitute anywhere.
- **Git attribution — which agent produced which commit — is computed on every scan and never read.** `app.ts:620-634`; `attributionRecordSchema` at `intelligence.ts:474-484` carries `commitSha`, `sessionId`/`agentId`, graded `confidence` (`:473`) and `reasons`; `intelligence-service.ts:1426-1447` emits `attribution.recorded` on every git scan. `api/project-scope.ts:127-134` maps no `attribution.` prefix.
- **Config drift, plans and snapshots are unreachable while their events stream into Activity.** Five read-only GETs at `app.ts:1176, 1181, 1199, 1204, 1219`, cleanly separable from the neighbouring mutation routes. Thirteen `config.*` event types (`runtime-event.ts:39-51`) with the prefix accepted at `realtime/schema.ts:56`, so the Activity row is the terminal surface.
- **Pair-scoped context reads are all unused**, so context bloat cannot be localised: `app.ts:570-575, 580-589, 1140-1148`; `contextFootprintSchema` carries `categories` and `exactDuplicateGroups` (`control-plane.ts:368-379`). Sharpest point: `docs/phase5-dashboard-capability-matrix.md:17` lists the pair-scoped `/api/v1/context/summary` inside a row marked SUPPORTED — the project's own plan counted this as in scope.
- **Usage is reduced harder than necessary.** `api/pulse.ts:149-157` keeps only `{source, recordCount, totalTokens}`, discarding the window (`observedFrom`/`observedTo`), `earliestAvailableAt`, and five per-source token breakdowns (`inputTokens`, `outputTokens`, `cachedInputTokens`, `cachedOutputTokens`, `reasoningTokens`, `contextUsedTokens`) already delivered by `usageSourceCompositionSchema` (`intelligence.ts:239-249`). Note the correction: `/api/v1/usage/summary` itself parses the full `usageListQuerySchema` (`app.ts:541-546`), so project/agent scoping needs no new endpoint.
- **Proposed actions are fetched and reduced to a count** at `api/intelligence-scope.ts:170`, though `proposedActions` arrives validated in the already-fetched collection (`intelligence.ts:799-821`). Rendering them costs zero extra requests. Proposal `summary` is likewise fetched and dropped, inconsistent with the Findings table directly above it, which renders its own summary (`optimization-view.tsx:60`). Evaluations are discoverable — `optimization.evaluation.completed` carries `evaluationId` and `proposalId` (`intelligence-service.ts:2148-2157`) — but there is no list endpoint and no evaluation reference on the proposal record.
- **Git branch/tag/worktree arrays are reduced to counts that are then never rendered** (`api/project-scope.ts:196-198`; `branchCount`/`tagCount`/`worktreeCount` appear in zero `.tsx` files), so the loss is total rather than partial. `/git/worktrees` (`app.ts:614-618`) is redundant with the observation; only `/git/commits` (`app.ts:603-613`) is a genuinely additional read. Recent commits themselves _are_ rendered (`projects-view.tsx:51, 65`).
- **Smaller graph items:** `toNode`/`toEdge` (`api/graph-explorer.ts:103-120`) drop `evidenceIds`, `observedAt`, `projectId` and most `metadata` that already arrived — the subgraph response uses the same full `graphNodeSchema` (`intelligence.ts:559-569, 630-634`), so the node-detail endpoint is redundant, as is the `/out` variant (`graph-explorer.ts:126-139` documents why only `/in` is fetched). Real: node `confidence` is fetched and never shown while edges do show Certainty (`graph-explorer-view.tsx:252-260` vs `:299-306`); the edge table renders raw entity ids (`:313-318`) though `data.nodes` holds a label for each; `/api/v1/graph/path` is unused; and `graph.*` events refresh only the summary (`intelligence-scope.ts:104`), so an open explorer does not reload after a rebuild.
- **Runtime identity:** `/api/v1/runtime` (`app.ts:360-378`) is unconsumed despite matrix line 11, and `version` is parsed then dropped (`api/pulse.ts:86-92`). Low value — `version` is a `z.literal` of the same constant compiled into the bundle (`runtime-http.ts:29`, `version.ts:2`), so it can never disagree, and restarts are already visible via `uptimeMs` at `pulse-view.tsx:286-288`. Only `runtimeInstanceId`, `workspaceId`, `protocolVersion` and `startedAt` are genuinely absent.

## 5. Test coverage

The suite is good where it exists — the empty/unavailable pairs, truncation disclosures, staleness chips and refresh states are all asserted. The gaps are specific:

- **Untested modules with real contracts:** `error-boundary.tsx` (29 lines, imported only by `main.tsx:329-331`; deleting `getDerivedStateFromError` leaves the suite green and white-screens the app) and `main.tsx` itself (333 lines, zero tests). `main.tsx` cannot even be imported by a test today — it calls `createRoot` at module scope and throws if `#root` is missing (`:324-333`). Its untested policies are the ones that matter: the intelligence gate (`:71-74, 142-152`), the clear-then-load project scope with its generation guard (`:160-171, 183-191`), the WebSocket-absent branch (`:244-251`) and the per-project event filter (`:269-275`).
- **`graph-diagram.tsx` (245 lines) has no direct test.** Its three deliberate encodings — the 26-node label threshold (`:33, :173, :180`), the unknown-kind fallbacks (`:90-104`), and `edgeStroke`'s confidence dasharray/opacity (`:107-115`) — are all pure functions testable without rendering. All three behave correctly today; this is regression risk.
- **GraphExplorerView:** the Node limit select (`:205-217`) is never changed (the truncation test at `graph-explorer-view.test.tsx:114` pins the default, not the setter); the `aria-busy` in-flight branch (`:220-223`) — the view's only loading signal — has zero matches in any test; the Root select (`:172-190`) and its `setSelectedId(undefined)` clear are untouched; the AbortController stale-response guard (`:131-141`) is unasserted. A superseded load resolving after a re-root would paint the previous root's subgraph under the new root's name.
- **App-shell states with no assertion anywhere:** "invalid realtime" (`app.tsx:280-284`), "Snapshot unavailable" (`:301-302`), "Validated snapshot" (`:306`), "Realtime unavailable"/"Realtime connecting"/"Realtime live" (`:126-127`), and the skip link (`:197-199`). The first two are degraded-path signals; "Realtime unavailable" is the only surface for the no-WebSocket environment `main.tsx:244-245` explicitly handles, and that branch is untested on both sides.
- **No `panel.test.tsx`.** The `ResourcePanel` precedence chain (`panel.tsx:88-96`) — the mechanism that keeps not-observed, unavailable and empty distinct — is exercised only incidentally, end-to-end, through the graph route and the Git resource.
- **`styles/shell.test.ts:6-13`** asserts four CSS source strings. Not wrong (jsdom computes no layout, so the behavioural alternative does not exist here), but the name promises more than the assertions establish, and the width/breakpoint literals break on a cosmetically identical custom-property refactor.

## 6. Depth and consistency

Not defects. Recorded because they shape how the UI reads.

- **Activity seeds 20 rows into a 200-row buffer.** `api/pulse.ts:176` requests `limit=20`; `realtime/activity-store.ts:3` retains 200; `runtime-api.ts:8-10` permits 1000. The filter dropdowns (`activity-view.tsx:41-43`) are derived from whatever the seed brought. The value is asserted by `pulse.test.ts:67` and documented against itself at `docs/phase5-dashboard-capability-matrix.md:15` ("limit=20" described as seeding "a live view bounded to 200 rows"), so changing it is a decision, not a silent fix. Correction worth keeping: live reconnection does _not_ re-seed — `main.tsx:226-233` merges with streamId dedupe; only bootstrap/retry resets (`main.tsx:89-96, 198-200`).
- **Agents is the thinnest route.** No `useState`, no filter, no sortable header, no inspector variant (`inspector-panel.tsx:10-13` has no `agent` case), against Sessions' two filters, three `aria-sort` headers and per-row Inspect (`sessions-view.tsx:71-95, 120-151, 159-173`). It is not interaction-free — `agents-view.tsx:51` renders a working `IdBadge` copy button per row.
- **Three renderings of the same primitive.** `IdBadge` on Sessions and Agents; raw `<code>` ids in `projects-view.tsx:308` and `graph-explorer-view.tsx:313-316`; plain text in the inspector (`inspector-panel.tsx:226-256`).
- **Pulse pays for a findings read on every load and renders none of it.** `findings` is in `pulseResourceKeys` (`api/pulse.ts:49-58`) at limit 100 (`:186`); `pulse-view.tsx` has no findings panel across all 340 lines; `snapshot.findingCount` (`pulse/model.ts:214`) is consumed nowhere. The read is not wasted — `#/optimization` reads it from the snapshot (`optimization-view.tsx:28-31`) — so the fix is to move it to the on-demand intelligence scope, matching the rule `main.tsx:65-74` already states.
- **Inspector selection survives route changes.** `selection` is component state (`app.tsx:163`), the hashchange listener only calls `setRoute` (`:175-179`), and the dialog renders whenever `selection !== undefined` (`:383-392`). Narrow: the backdrop closes on any outside mousedown (`inspector-panel.tsx:197-203`), so only Back/Forward or hand-editing the hash can produce the mismatch.
- **Graph explorer can latch into a permanent "Reading the bounded subgraph".** If it mounts with zero projects, agents _and_ sessions, `root` stays undefined (seeded once at `graph-explorer-view.tsx:124`, never re-synced to `seeds`), the load effect returns immediately and its deps never change (`:131-141`; `loadSubgraph` is bound once at `main.tsx:54-58`), and `app.tsx` renders the view with no `key`, so later seeds are a prop change rather than a remount. Recoverable by touching the Root select. Narrow, but it is a dead state.
- **Design-system drift, cosmetic only:** `tokens.css` ships no type tokens, so every size is a literal; `.inspector h2, h3` (`activity.css:143-146`) is the _only_ rule targeting those elements and sets `margin: 0` alone, so they fall through to UA defaults (~21px / ~16.4px over a 14px base). The spacing scale (`tokens.css:50-55`) is consumed by `projects.css` only (23 references) and by `shell.css`/`pulse.css`/`activity.css` zero times, which carry 78 raw px declarations, roughly a fifth off the 4px rhythm the audit accepted (`docs/phase5-dashboard-mockup-audit.md:24`). Four different letter-spacings for one uppercase-mono label idiom (0.13/0.08/0.06/0.04em). Two selected-row conventions (`projects.css:57-63` vs `:357-359`). `.table-filters select` has no `:focus-visible` rule (`projects.css:220-229`) but also no `outline: none`, so it keeps the UA ring — inconsistent, not inaccessible.

## What is NOT a gap — leave these closed

- **No mutation UI anywhere.** The read-only posture is AGENTS.md §21 and holds throughout; nothing in this audit contradicts it. Where a domain has both read and write routes (config plans/snapshots/drift), only the read half is reported.
- **Lifecycle/release scoring, task/lease systems, unified search, semantic or vector knowledge graph, GitHub integration, authentication, cloud accounts** — no finding touches any of them, and `product-independence.test.ts:28-73` already guards the boundary.
- **Pulse not reading `/api/v1/graph/summary`.** `main.tsx:65-74` keeps it off the bootstrap because ADR 0013 prices it at 56 Redis commands. The defect is the hardcoded Pulse row, not the missing read — wiring Pulse to the summary would be the wrong fix.
- **Inspectors not being URL-addressable.** `routing.ts:19-32, 69-77` deliberately parameterises only `projects`. Unbuilt, not broken.
- **The DS jewel family and blue identity trio absent from `tokens.css`.** The DS scopes those to per-product theming (`readme.md:17-18`) and this is one product; `--luwi-accent-hi`/`-lo` are already carried in substance as `--magnitude-fill`/`--focus` (`tokens.css:29, 59`). Only the stray `#a78bfa` literal is a real item.
- **Route heading `h2` sizes differing between a route heading (22px) and a panel header (14px)** — contextual hierarchy, not drift. And strike the "11px violates the audit" claim entirely: the rule is "metadata below 11px is raised to at least 12px" (`docs/phase5-dashboard-mockup-audit.md:78`), which 11px satisfies.
- **No dimension came back clean**, but two came back mostly clean in substance: evidence-honesty discipline is right almost everywhere (the four violations above are exceptions in a codebase that documents the rule in source comments), and no finding proved a single outbound network request, CDN reference, or webfont.
